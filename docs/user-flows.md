# User Flows

## Purpose
This document outlines the key user journeys through the Chromapages marketing website. These flows define how visitors should move from awareness to action, and where the site needs to reduce friction, answer objections, and create confidence.

These are not app-style product flows. They are marketing-site flows focused on lead generation, trust-building, and qualification.

---

## Flow 1: Homepage To Discovery Call

### User Goal
The user wants to quickly understand what Chromapages does and decide whether to book a call.

### Entry Points
- direct traffic
- referrals
- branded search
- social profile links
- outbound prospecting links

### Steps
1. User lands on the homepage
2. User scans hero section to understand offer and positioning
3. User reviews proof elements and service overview
4. User checks supporting trust sections like work, process, or FAQ
5. User clicks primary CTA
6. User is taken to booking link, contact page, or qualified form
7. User completes action
8. User reaches thank-you or confirmation state

### Key Friction Points
- unclear value proposition
- not enough trust early
- weak proof
- too much text before CTA
- unclear next step

### Success Condition
- booking completed
- or qualified inquiry submitted

---

## Flow 2: Homepage To Services To Contact

### User Goal
The user needs more detail before contacting Chromapages.

### Entry Points
- homepage
- referral traffic
- internal navigation

### Steps
1. User lands on homepage
2. User clicks into Services
3. User scans top-level services overview
4. User reviews one or more service categories
5. User determines relevance and fit
6. User clicks CTA to contact or book a call
7. User submits form or books

### Questions The User Is Asking
- do they offer what I need?
- do they understand my type of project?
- is this service too big or too small for me?
- what happens after I reach out?

### Success Condition
- user transitions from informational browsing to direct inquiry

---

## Flow 3: Service Detail Page To Contact

### User Goal
The user wants to validate one specific service before taking action.

### Entry Points
- organic search
- paid campaigns
- internal links from Services page
- shared direct links

### Steps
1. User lands on a service page
2. User reads the service promise and who it is for
3. User reviews outcomes, process, and scope framing
4. User checks proof or related work if available
5. User sees CTA tied to that service
6. User clicks through to contact or booking
7. User completes inquiry

### Key Friction Points
- service page too vague
- no proof or relevance
- too much jargon
- no clear fit explanation
- CTA feels premature or disconnected

### Success Condition
- qualified contact intent generated from a service-specific page

---

## Flow 4: Work / Case Study To Contact

### User Goal
The user wants proof before reaching out.

### Entry Points
- homepage featured work
- Work page
- organic search to case study
- referral links

### Steps
1. User lands on Work overview or a case study page
2. User scans project relevance
3. User reads project summary, approach, and results
4. User builds trust through proof
5. User clicks CTA to contact or book
6. User completes inquiry

### What This User Needs
- confidence that Chromapages can execute
- reassurance that real outcomes matter
- a sense that projects are handled professionally

### Success Condition
- trust is strong enough to trigger conversion

---

## Flow 5: Pricing To Contact

### User Goal
The user wants to understand investment range and fit before reaching out.

### Entry Points
- top nav
- homepage pricing preview
- internal links from service pages
- direct referral to pricing

### Steps
1. User lands on Pricing page
2. User reviews engagement types or ranges
3. User understands how scope changes pricing
4. User self-qualifies
5. User clicks CTA to discuss project
6. User submits inquiry or books call

### Key Friction Points
- pricing feels too vague
- pricing feels too rigid
- no explanation of who each option is for
- visitor cannot place themselves in a clear offer path

### Success Condition
- better-fit leads move forward
- poor-fit leads self-select out

---

## Flow 6: Contact Form Submission

### User Goal
The user is ready to reach out and wants a clear low-friction way to do it.

### Entry Points
- Contact page
- CTA buttons across site
- service page CTA
- pricing CTA
- final CTA sections

### Steps
1. User lands on Contact page or form section
2. User scans short intro and what happens next
3. User fills out qualification form
4. User submits
5. User sees success state or thank-you page
6. User understands the next step in the process

### Required Form Experience
- short enough to complete quickly
- structured enough to qualify the lead
- confidence-building language around response expectations
- clear submission confirmation

### Success Condition
- form submitted successfully
- user knows what happens next

---

## Flow 7: Referral Visitor Fast-Track

### User Goal
The user already has some trust from a referral and wants to verify credibility fast.

### Entry Points
- direct homepage
- direct Work page
- direct Contact page
- service page shared by referral partner

### Steps
1. User lands on page from referral source
2. User scans for credibility and fit
3. User checks proof or process quickly
4. User moves to contact or booking
5. User submits or books

### Design Implication For Structure
This user may skip a lot of the narrative. The site still needs:
- obvious CTA access
- fast trust markers
- easy navigation to proof and process

### Success Condition
- fast conversion with minimal friction

---

## Flow 8: Organic Search Visitor To Service Fit

### User Goal
The user is searching for a solution and arrives on a specific page.

### Entry Points
- service detail page
- blog/article page later
- work/case study page
- pricing page

### Steps
1. User lands on page from search
2. User evaluates whether Chromapages solves the exact problem
3. User looks for supporting proof and credibility
4. User checks service fit and next steps
5. User converts or explores deeper

### Requirements
- each entry page must stand on its own
- internal links should help the user move naturally to deeper proof or contact
- CTA logic should be clear but not pushy

### Success Condition
- search visitor moves from cold intent to qualified interest

---

## Global Flow Principles

### 1. Every Core Page Needs A Next Step
No important page should dead-end. Each one should offer:
- contact
- booking
- work review
- service detail progression
- related proof or process links

### 2. Trust Must Show Up Early
Most users decide quickly whether to keep reading. Trust cues should appear near the top of key pages.

### 3. The Site Should Qualify, Not Just Attract
The site should help the right leads move forward and help the wrong leads self-select out.

### 4. Contact Must Feel Easy
Users should never wonder how to start. Contact paths should stay visible and low-friction.

### 5. Confirmation Matters
After a form or booking action, the user needs a clear success state and expectation for what happens next.

## Recommendation
When building pages, validate each one against a simple question:

**What is the user trying to do here, and what is the clearest next step we want them to take?**
