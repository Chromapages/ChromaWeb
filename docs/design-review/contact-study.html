Layout notes · outside page composition

Form first, clear labels, honest states.

C1 · Purpose and hierarchy

The short heading and proposed task copy come from copy-review §5. Desktop: form in the first eight-column zone, max640px, advice in the final four. Below1024: form then advice. DOM and visual reading order match. There is no self-linking “Book A Call” hero action.

C2 · Native request choice

The radios use native fieldset/legend, checked and keyboard behavior. CSS switches only the visible message/action text; common entries are retained. No custom tab roles, roving-focus script or new service value. Full production submission remains the current RequestForm/API responsibility.

C3 · Unknown optional choices

Project-type and budget options are unapproved sources, so this proposal omits those optional controls. They may be restored prospect-only using approved existing options and blank initial values. No new mandatory field, numerical range or Rescue Sprint definition is invented. Name/email/message requirements match the current schema.

C4 · State and focus contract

Use the shared error/success colors from core §3.6 and persistent field labels from §14.5. Submit is solid Teal with8px radius per §8. Validation summary links, receipt focus, frozen pending inputs and explicit reset are specified in the README. The preview contains no submission script and makes no backend claim.

C5 · Responsive and motion behavior

Core §§4–7 govern typography,20/32/48/80 outer margins,24px field gaps,8px controls and12px panel. At narrow widths every field/action spans the available column;16px input text and6-row textarea remain readable. No animation is needed; reduced-motion removes hover transitions. Verify320px/zoom/keyboard layouts when capture becomes available.
