## Versioning Guidance

### Suggested Format
Use semantic-style versioning for documentation and project milestones where useful:

- `0.x.x` for early pre-launch iterations
- `1.0.0` for the first full launch-ready release
- increment minor versions for meaningful documentation/build changes
- increment patch versions for small fixes and clarifications

### Example
- `0.1.0` — initial docs baseline
- `0.2.0` — content and structure revisions
- `0.3.0` — technical and launch-readiness updates
- `1.0.0` — first production launch

---

## Change Log Rules

When adding entries:
- use the release date
- keep items specific
- group by Added / Changed / Fixed / Removed when relevant
- note structural or strategic changes, not just tiny wording edits unless they matter
